# Academy Toolkit

## Overview
Academy Toolkit is a web application designed for private practice video marketing professionals. It provides tools to upload videos, receive AI-powered transcriptions, and get scoring and improvement suggestions based on a 5-part video formula: Hook, Set the Hook, First CTA, Content, and Final CTA. The platform also offers comprehensive email marketing tools, a daily method of operation tracker, and a personalized dashboard. Key capabilities include AI-powered video analysis, email sender reputation monitoring, inbox analysis, and competitor email intelligence, all aimed at enhancing marketing effectiveness for private practices.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture

### Core Technologies
- **Frontend**: React 18, TypeScript, Vite, Wouter, TanStack React Query, shadcn/ui (Radix UI), Tailwind CSS, React Hook Form with Zod.
- **Backend**: Node.js, Express, TypeScript (ESM), RESTful JSON API.
- **Data Storage**: PostgreSQL with Drizzle ORM.
- **File Storage**: Local filesystem with architecture designed for future S3 migration.

### Design Decisions and Features
- **Monorepo Structure**: Organized into `client/`, `server/`, and `shared/` for type-safe development.
- **User Authentication**: Custom session-based authentication with bcrypt hashing.
- **AI-Powered Video Analysis**: Utilizes AI for transcription and scoring against a 5-part video formula, with feedback tailored to user goals (sales, lead, education, recruit). Users can retranscribe up to 3 times.
- **Video Processing**: Audio-first processing for rapid transcription, with parallel generation of HLS streams and video previews.
- **Reporting**: Downloadable branded PDF reports of session scores.
- **Email Tools Hub**: Central hub for email marketing, including:
    - **Sender Reputation**: Integrates with Google Postmaster Tools for domain reputation.
    - **Inbox Analyzer**: Provides detailed email analysis (authentication, sender trust, spammy language, technical health, content quality, CAN-SPAM compliance) using unique seed addresses.
    - **Inbox Placement Monitoring**: Tracks email placement across various seed inboxes using Google OAuth.
- **DMO Tracker**: Tracks daily activities, streaks, points, and milestone badges.
- **Dashboard**: A live command center with a calmer, more uniform palette (neutral cards with thin single-color top accent rules instead of multi-stop gradient fills). Layout: hero header with personalized greeting + 2 actions (Open Projects, Log DMO) and a 3-KPI ribbon (DMO points today, Open tasks, Competitor emails 7d); **Row 1** — **Projects hero** (large, `lg:col-span-2`, `card-projects-hero`) with stat chips (Projects, Open tasks, Due 7d, Overdue) and a prominent "Up Next" task list scoped to **this week only** — top 8 tasks across all active projects, grouped Overdue/Today/This week (tasks without a due date and tasks dated further out are intentionally hidden), each row showing project color dot + project name + colored due pill and linking to `/projects/:id` plus a "Top projects" mini-strip with progress bars — fed by `GET /api/projects/all-tasks` + `GET /api/dashboard/projects`; alongside it the **Email Health** tile (Sender Reputation + Inbox Placement, emerald accent only); **Row 2** — DMO Streak / Inbox Analyzer / Competitor Pulse (3 equal smaller tiles); **Row 3** — Recent Activity (full-width, last 7 events from sessions/emails/scripts/anomalies). The legacy Video Practice tile has been removed from the dashboard.
- **Teleprompter**: A standalone, members-only tool for scrolling pre-written scripts with customizable display settings and server-side persistence.
- **ClickFunnels Integration**: Manages app access based on ClickFunnels enrollment, provides SSO, and enforces membership checks.
- **Admin Panel**: Provides detailed user management, including ClickFunnels membership status, account actions, and integration health monitoring for ClickFunnels and Keywords Everywhere. **User Details sheet** (eye icon): gradient header card with initials avatar + display name + email + role/disabled/membership/joined badges, 2x2 stats grid (Video sessions, KW credits month/total, Last login, Account age), ClickFunnels Membership card (status, enrolled/revoked timestamps, CF Contact ID), Account & Sign-in card (click-to-copy User ID, names, theme, disabled-at/reason, sign-in methods), Recent Video Sessions list (clickable to open session detail), and Admin Actions footer; legacy "Consent & Marketing" section removed. **Action History sheet** (activity icon): violet-gradient header card (initials avatar + name + email + Admin badge + "<N>+ loaded" badge with "<N> matching" appended when filter active), filter dropdown driven by `ACTION_TYPE_OPTIONS` (client-side filter on loaded set), day-grouped timeline with sticky "Today / Yesterday / <Weekday>, <Mon> <D>, <YYYY> · N actions" headers, per-action rows with colored icon (via shared `getActionVisual`), action label, time-of-day, entity type + first-8-chars of ID, device chip parsed from user-agent (iOS/Android/Mac/Windows/Linux/Other), IP address, and a "Show details" toggle that expands metadata JSON in a pretty-printed `<pre>`. Empty states differentiate "no actions yet" vs. "no actions match this filter" (with Clear filter button). "Load older actions" uses existing cursor pagination; `onOpenChange` resets filter + expanded-meta on close. Backend `GET /api/admin/users/:id` now returns `totalVideos`, `keywordsCreditsThisMonth`, `keywordsCreditsTotalUsed`; `GET /api/admin/users/:id/actions` now returns `ip` and `userAgent` per item.
- **Account Page**: Members-only page for profile management, membership status display, **per-user time zone setting** (emerald "Time zone" card with searchable IANA select + "Use my browser time zone" shortcut), and a log of recent user activities.
- **Time Zone**: Each user has a `timezone` column on `users` (IANA, default `America/New_York`, NOT NULL). The selected zone drives "today / this week" math everywhere it matters — both **server-side** (DMO streak boundaries via `getDmoStreak`; project task "due this week" + "overdue" counts via `(due_date AT TIME ZONE $tz)::date` in `getProjectsForUser` / `getDashboardProjectsSummary`) and **client-side** (DMO date key via `Intl.DateTimeFormat("en-CA", {timeZone})`; dashboard "Up Next" bucketing + due-pill labels in `dashboard.tsx`; projects hub card pills, List grouping, and Calendar grid in `projects.tsx`; project-detail task badges + project-due hero pill in `project-detail.tsx`; Inbox Intel feed "Today/Yesterday" headings + date-preset windows in `inbox-intel-feed.tsx`). `/api/auth/me` and `/api/account` both return `timezone`; `PATCH /api/account` accepts and validates it. Helpers live in `shared/datetime.ts`: `safeTimezone`, `todayKeyInTz`, `addDaysToKey`, `getCommonTimezones`, `formatInTz`, plus `dueDateKey(due, tz)` (UTC-midnight values treated as date-only calendar days; otherwise resolved in tz), `dayDiffInTz(due, tz, ref?)` (whole-day delta), and `dueHasTime(due)`. Saving the zone immediately invalidates the dmo/projects/dashboard queries.
- **Help Documentation**: In-app hub with illustrated guides for all features.
- **Projects**: Lightweight Asana-style project manager for members. The hub page (`/projects`) has four top-level tabs (`projects-top-tab` localStorage key): **Overview** (cards/list of projects with Active/Archived sub-tabs and the Cards/List view toggle, plus the Urgent-Tasks banner), **List** (all open tasks across every active project, grouped Overdue/Today/This week/Later/No due date with project color dot + name + due pill), **Calendar** (6-week month grid with tasks plotted on their due date, prev/today/next nav), and **Templates** (per-member reusable project blueprints — name/description/color + tasks with notes/priority/tags/links + one-level subtasks; **no due dates or status on template tasks**, dates are picked after a project is created from the template). The "New Project" dialog includes a **Start from** picker (Blank or any of the user's templates); choosing a template clones its tasks into the new project with `status="todo"` and `dueDate=null`. Each template card has Edit/Duplicate/Delete in a kebab menu plus a "Use template" action; the project-detail header has a **Save as template** menu item that snapshots the project into a new template. Template editor lives at `/projects/templates/:id` and reuses the task list pattern but hides status/due-date UI. Backend tables `project_templates` and `project_template_tasks` (cascade delete; one-level subtask invariant enforced server-side); routes under `/api/project-templates*` and `/api/template-tasks/*` are auth-gated and userId-scoped, plus `POST /api/projects` accepts an optional `templateId` and `POST /api/projects/:id/save-as-template` snapshots an existing project. List + Calendar both feed from `GET /api/projects/all-tasks` (storage `getAllOpenTasksForUser` — non-done tasks under active projects, ordered by due_date with NULLs last; returns `projectName` + `projectColor`). Each project has a name, description, color, status (active/archived), and an optional due date (date-only, set/cleared via the create + edit dialogs; surfaced as a colored pill on the project card — rose=overdue, amber=today/tomorrow, sky≤7d, muted=future — and as a tinted pill in the project detail header); each project contains tasks with one level of subtasks, status (todo/in_progress/done), priority (none/low/medium/high/urgent), due date+time, external URL links (http(s) only), and Tiptap-powered WYSIWYG notes. Hub page (`/projects`) shows project cards with progress bars, task counts, and Active/Archived tabs; detail page (`/projects/:id`) shows tasks grouped by status with quick-add per group and a side sheet for editing every task field. The Dashboard includes a Projects widget surfacing the top 3 active projects, total Active/Open/Due-7d stats, and an overdue alert. The task detail panel reuses itself for subtasks with prominent amber breadcrumb bars at top and bottom for back navigation, and includes a **Comments + Activity** tabs section below the Subtasks list — comments render as chat bubbles with author avatars (initials), Cmd/Ctrl+Enter to post, per-comment delete and inline edit for the author (Edit reveals an autofocused textarea with Save/Cancel; Cmd/Ctrl+Enter saves, Esc cancels; an "(edited)" marker appears next to the timestamp when the comment has been modified); the Activity timeline auto-logs `created`, `status_changed`, `priority_changed`, `due_changed`, `title_changed`, `notes_changed`, `links_changed`, `subtask_added`, `comment_added`, and `comment_edited` with color-coded icons and human-readable descriptions. Backend tables `projects`, `project_tasks` (cascade delete), `task_comments`, `task_activity` (both cascade on task delete); all routes under `/api/projects*` and `/api/tasks/*` are auth-gated and userId-scoped, with server-enforced one-level subtask invariant. Comment edit (`PATCH /api/tasks/:taskId/comments/:commentId`) and delete are both restricted to the comment author; edits bump `updated_at` and log a `comment_edited` activity entry.
- **Inbox Intel**: Competitor email intelligence tool allowing users to track competitors' email communications. It captures, parses, and stores incoming emails from unique seed addresses, providing detailed analytics on sending cadence, send volume, subject line stats, ESP fingerprinting, authentication audits, and content patterns. Features include a unified feed for cross-competitor analysis, website screenshot capture for competitor tiles, and rule-based funnel detection for welcome sequences. Upcoming features include cross-competitor insights and comparison tools, and CSV export functionality for email data.

## External Dependencies

### AI Services
- **Google Gemini API**: For video transcription.
- **OpenAI API**: For transcript scoring and feedback generation.

### Database
- **PostgreSQL**: Primary database for all application data.

### Email Services
- **SMTP**: For sending password reset emails and system notifications.
- **SendGrid**: For receiving inbound parsed emails for the Inbox Analyzer.

### OAuth Providers
- **Google OAuth**: For user authentication, Google Postmaster Tools integration, and Inbox Placement Monitoring (Gmail access).

### Third-Party APIs
- **ClickFunnels API**: For membership enforcement and SSO.
- **Microlink (`api.microlink.io`)**: For capturing website screenshots for Inbox Intel.
