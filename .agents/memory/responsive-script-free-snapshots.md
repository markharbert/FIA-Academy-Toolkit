---
name: Responsive script-free snapshots
description: Keeping Responsive Preview snapshots functional for CSS testing without sandbox script warnings.
---

Responsive Preview must keep captured page content script-free. Its sandbox should have no permissions at all, and the preview iframe should stay inside a shadow-root mount rather than the page's light DOM.

**Why:** Captured pages can contain nested iframes or inline script entry points even after top-level `<script>` tags are removed. Any script or origin permission is unnecessary for the sanitized CSS/media-query preview and can create browser sandbox warnings. Shadow isolation prevents page scripts from targeting the frame, while sanitization removes executable content.

**How to apply:** When updating snapshot generation, remove script, noscript, template, iframe/frame, object, and embed nodes; strip inline `on*` attributes and `javascript:` URLs. Keep the actual preview iframe in a shadow-root mount, use an empty sandbox attribute, and retain tests that it is absent from light DOM, no script-capable content enters the preview, and sandbox configuration matches the sanitized model.

**Critical parsing gotcha:** `<noscript>` (and `<template>`) content is inert text on a normal scripting-enabled page, so DOM cloning preserves it invisibly — but a script-disabled sandboxed `srcdoc` re-parses that serialized content as REAL markup. WordPress/GTM tracking `<noscript><script>/<iframe>` fallbacks then become live nodes and Chrome logs "Blocked script execution in 'about:srcdoc'…" per node. Any regression fixture must include noscript-wrapped script/iframe markup, and warning collection must be scoped to the Responsive lifecycle only (reset collectors right before injection) or pre-existing page warnings and other tools' synthetic-event errors pollute the assertion.

**Additional hardening (assign srcdoc before attach + CSP attr):** Set `frame.srcdoc` BEFORE appending the iframe to the DOM so there is never a window where an empty `about:blank` frame is in the tree. Add an iframe `csp` attribute with `script-src 'none'; object-src 'none'` as defence in depth. Keep the shadow root `mode:"open"` — Chrome's cross-origin policy already blocks page scripts from reaching into the sandboxed frame (a hostile-page MutationObserver injection test throws SecurityError and logs no warning), so a closed root adds no security but breaks tests because `executeScript` runs in the isolated world (page-world `evaluate` cannot see `window.__fiaResponsive`; cross-world checks must go through the DOM/shadowRoot or `dataset`).

**Scrolling gotcha (pointer-events:none):** Putting `pointer-events:none` on the preview iframe freezes the snapshot at the top — wheel/touch events never reach the sandboxed document, so tall pages look "stuck" at every device size. Fix: keep pointer input enabled (scrolling needs no scripts, so the empty sandbox is unaffected), inject a small style into the snapshot making interactive elements (`a, button, input, …`) `pointer-events:none` so clicks can't navigate or submit, and add a window-blur focus guard that pulls focus back out of the frame so Escape keeps closing the tool. The focus target must be a focusable element (`tabindex="-1"` on the workspace div).

**Verifying against the user's real page:** When a sandbox warning is reported on a specific site, fetch that exact live URL, extract the shipping `buildPageSnapshot` from responsive.js, run it in a real Chromium tab against the fetched HTML, inject the output into an identical `sandbox=""` srcdoc iframe, and count blocked-script warnings. This tests the true page, not a synthetic fixture. Also note: Chrome DevTools' Errors panel persists entries with no timestamp until "Clear all", so a reported warning can be stale from a previously-loaded extension version — always confirm the loaded version and a cleared log before trusting a repro.
