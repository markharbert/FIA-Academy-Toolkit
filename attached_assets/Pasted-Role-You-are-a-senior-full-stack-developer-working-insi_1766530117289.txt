Part 1: Cache Keap Tags

Goal
When the admin fetches Keap tags, store them in our database so we can reuse them without hitting Keap every page load.

Database changes
Add to SystemSettings (or equivalent app settings store):

keapTagsCacheJson (text/json, nullable)

keapTagsCachedAt (datetime, nullable)

keapTagsCacheExpiresAt (datetime, nullable)

keapLastTagFetchError (text, nullable)

Caching rules

Cache TTL: 72 hours.

When the admin page loads:

If keapTagsCacheJson exists AND current time < keapTagsCacheExpiresAt:

Use cached tags.

If missing or expired:

Auto refresh in the background if Keap is connected.

If refresh fails, continue showing cached tags if present, and show a warning.

When admin clicks “Fetch tags”:

Force refresh tags from Keap immediately.

Overwrite cache and reset cachedAt and expiresAt.

Tag object format to cache
Store as array of:
[{ "id": "<string or number>", "name": "<string>" }]
Sort by name before caching.

API changes
Implement or update endpoints:

GET /api/admin/keap/tags
Behavior:

Returns tags quickly from cache when valid.

Accepts query param:

force=true to bypass cache and fetch from Keap.
Return JSON:
{
"source": "cache" | "keap",
"cachedAt": "...",
"expiresAt": "...",
"tags": [...]
}

POST /api/admin/keap/tags/refresh
Behavior:

Forces a refresh regardless of cache.

Returns the same payload as above.

Backend logic requirements

Use getKeapAccessToken() helper.

If not connected, return 400 with a friendly message.

If Keap request fails:

Log the error

Set keapLastTagFetchError in settings

Return cached tags if available and mark source="cache" plus warning field.

Background auto refresh
Implement one of these:
Option A (recommended): On admin page load, call GET tags, and if expired it refreshes automatically server side.
Option B: A scheduled job that runs every X hours to refresh when connected.
Either is acceptable, but must meet the behavior: auto refresh after 72 hours without admin needing to click.
