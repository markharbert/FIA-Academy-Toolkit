Role: You are a senior full stack developer debugging an existing Replit web app. The Keap OAuth connection flow redirects to Keap successfully, but after interacting with Keap it shows: “There was a server error processing your request.” That message is shown on the Keap side, which usually means our OAuth app configuration, redirect URI, scopes, or authorization request parameters are wrong, or our app is failing to complete the OAuth flow correctly.

Your job:

Find the exact root cause of the Keap server error.

Fix Keap OAuth connect end to end.

Add reliable tag selection so every new signup can be tagged in Keap with an admin chosen tag.

Provide clear setup steps and verification evidence.

Do not guess. Use logs, response codes, and captured request URLs to pinpoint the issue.

Part 1: Reproduce and capture the exact failure

Reproduce the Keap connect flow from the Admin Keap Integration page.

Capture the full Keap authorize URL we send the user to, including query parameters:

client_id

redirect_uri

response_type

scope

state

Capture the exact screen in Keap where it says “server error processing your request.”

Check whether Keap redirected back to our app at all.

If yes, capture the callback URL query string (code, state, error, error_description).

If no, the error is happening before callback, likely due to invalid authorize request parameters.

Add temporary logging

Log the generated authorize URL on our server (redacting nothing except secrets).

Log the redirect_uri value exactly.

Log the scope value exactly.

Log state generation and storage.

Part 2: Verify Keap OAuth configuration and parameters

You must validate each of these and fix mismatches:

Client ID and Client Secret

Confirm env vars exist and are loaded:

KEAP_CLIENT_ID

KEAP_CLIENT_SECRET

KEAP_REDIRECT_URI

KEAP_AUTHORIZE_URL_BASE

KEAP_TOKEN_URL

Log which vars are present (never log secrets).

Confirm the app is not using stale or wrong credentials.

Redirect URI mismatch
This is the most common OAuth failure.

Confirm KEAP_REDIRECT_URI exactly matches what is configured in the Keap developer app settings, character for character.

Confirm correct scheme (https vs http).

Confirm correct path (for example /api/admin/keap/callback).

Confirm no trailing slash mismatch.

Confirm no URL encoding mistakes.

Authorize endpoint correctness
Keap has had different hostnames historically.

Identify what the current correct authorize base should be for Keap.

Use the Keap official docs currently referenced in the codebase and confirm:

The authorize URL is correct

The token URL is correct (often https://api.infusionsoft.com/token
)

Make the authorize base configurable via env var, defaulting to the correct one.

Required query parameters
Ensure authorize request includes:

client_id

redirect_uri (URL encoded)

response_type=code

scope (space separated or encoded as required)

state (random, stored server side)

If any are missing or malformed, fix.

Scope issues

Confirm the scopes requested are valid Keap scopes.

Reduce to the minimum needed for:

creating and updating contacts

applying tags

reading tag list (optional but recommended)
If scopes are invalid or too broad, Keap may error.
Implement a configurable KEAP_SCOPES env var with a safe default.

State and CSRF

Ensure state is random and stored server side (session or DB).

Ensure callback validates state.

If state mismatch occurs, show a clear error on our side, not generic.

/api/admin/keap/callback

Add structured logs with a traceId:

Query params present:

code

state

error

Exchange code for tokens at KEAP_TOKEN_URL

Log status code

Render a clear admin error page with next steps

Important token storage rules

Persist the newest refresh token after refresh calls.

Part 4: Confirm Keap token refresh works and is used correctly

Implement helper:
getKeapAccessToken()

Rules:

If token missing, return not connected.

If token expires within 5 minutes, refresh it.

On refresh, update:

access token

refresh token

expiresAt

lastRefreshAt

If refresh fails, store lastError and show it in admin UI.

syncUserToKeap(user)
