PART 2: Backend Flow Must Not Depend On Frontend Redirects

Problem to solve
Today there is a disconnect between upload and session processing. Fix by making upload finalization trigger processing server-side.

Required server workflow

User starts upload from the Session page.

Backend creates a session immediately and returns sessionId.

Upload completes for that sessionId.

On upload complete, the backend MUST:

Validate file

Enqueue processing pipeline

Update session status to processing
This must happen automatically server-side, not dependent on a second page load.

End-to-end steps

POST /api/sessions/create

Creates session row

Returns sessionId

Upload endpoints attach the upload to sessionId

POST /api/sessions/:id/upload/complete

Validates that the file exists and is readable

Sets processingStartedAt

Enqueues processing job

Returns success and session status

The Session page will then:

Poll or subscribe to progress updates for that sessionId

Render player and results when ready

PART 5: Fix “Download PDF Report” (Currently Downloads JSON)

Current bug
Clicking “Download PDF Report” downloads a JSON file. That means the endpoint is returning JSON or the frontend is treating the response incorrectly.

Required behavior
The button must download an actual PDF file.

Backend requirements

Implement a dedicated PDF endpoint:
GET /api/sessions/:id/report.pdf

It must:

Require auth and ownership (or admin)

Return Content-Type: application/pdf

Return Content-Disposition: attachment; filename="Fearless-Video-Coach-Report.pdf"

Return actual PDF binary data

If you already have a JSON endpoint like /api/sessions/:id/report

Keep it for internal data

But the download button must call the .pdf endpoint.

Frontend requirements

The download button must:

Request the PDF endpoint with correct headers

Treat the response as a blob

Trigger a browser download of a .pdf

Do NOT parse JSON.

Confirm that the filename ends in .pdf.

If report needs generation

Generate on demand if not cached.

Or generate at session ready and store a PDF file key.

If transcript or recommendations change, mark PDF stale and regenerate.
