PART 1: Persist the Preview Video and Always Show It Until Expiration

Problem to solve
Videos sometimes load inconsistently after updates. We need a durable persistence model and a deterministic way to load the preview asset on every page load.

Required backend data model
On session processing completion for the preview video, persist these fields in the Sessions table:

previewVideoStorageKey (string, required once ready)

previewVideoMimeType (always video/mp4)

previewVideoGeneratedAt (datetime)

previewVideoSizeBytes (int)

previewVideoDurationSeconds (float)

previewVideoExpiresAt (datetime, equals session.expiresAt)

previewVideoStatus (queued | generating | ready | failed)

previewVideoError (nullable)

Session expiration rules

The preview video remains available until session.expiresAt (30 days after creation).

A cleanup job deletes the previewVideoStorageKey file at expiration.

Required API behavior on every Session page load
GET /api/sessions/:id must ALWAYS return a stable payload describing preview availability:
{
"id": "...",
"title": "...",
"expiresAt": "...",
"video": {
"mode": "mp4",
"status": "ready" | "generating" | "failed",
"previewUrl": "..." (present if ready),
"posterUrl": "..." (present if ready),
"generatedAt": "..."
}
}

Preview URL generation

Derive previewUrl from previewVideoStorageKey.

If the storage requires auth, either:
A) Serve it via an authenticated streaming endpoint:
GET /api/sessions/:id/video/preview/stream
or
B) Generate a signed URL on request.
Pick one approach and make it consistent across environments.

No empty player rule
If video.status is “ready” and previewUrl exists, the UI must render the player with src=previewUrl. If not ready, show the rendering meter and placeholder.

PART 2: Make Preview Video Playback Reliable

If using a backend stream endpoint, it must:

Require auth and ownership/admin.

Stream the file with correct headers:

Content-Type: video/mp4

Accept-Ranges: bytes

Handle Range requests:

Return 206 Partial Content when Range header exists.

Never return an HTML page on auth failure. Return 401 JSON.

Frontend must:

Only mount the <video> element once previewUrl exists.

Force remount on URL changes:

<video key={previewUrl} src={previewUrl} controls preload="metadata" playsInline poster={posterUrl} />

After previewUrl updates:

call videoRef.load()

Requirement

example: width 640, maintain aspect ratio

previewPosterStorageKey

previewPosterGeneratedAt

Set the video tag poster attribute to posterUrl.

Ensure posterUrl is accessible with the same auth model as previewUrl.
