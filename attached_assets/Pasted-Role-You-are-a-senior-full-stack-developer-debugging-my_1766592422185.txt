PART 3: Identify the Most Likely Root Causes and Fix Them

You must check and fix these common issues in order:

A) Request size limits / reverse proxy limits

Confirm server upload limit settings.

In Node/Express, ensure body parsers are not used for raw binary upload endpoints.

If using a platform proxy, ensure max size is not exceeded.

B) Storage write failures

If saving to filesystem:

confirm write path exists and is writable

confirm free disk space

confirm filename sanitization

If saving to object storage:

confirm credentials, bucket, CORS, and pre-signed URL expiration

confirm multipart complete call is valid

C) Chunked upload mismatch (if chunked)

Ensure all parts are uploaded and accounted for

Ensure part numbers are correct

Ensure server assembles chunks in correct order

Ensure final file size matches expected

D) MIME and format validation rejecting the file after upload

If ffprobe runs after upload, it may be failing.

Capture ffprobe stderr.

If ffprobe fails, return a clear error:

“We uploaded your file but could not read it for processing.”

E) Wrong endpoint paths or 404/router issues

Confirm every endpoint exists in the published environment.

Ensure frontend calls the correct path prefix.

F) Auth/session credentials missing on one request

Ensure fetch includes credentials.

Ensure CSRF requirements are met if enabled.
