Current issue

Required behavior

Tags must be stored server side in the database, not only in frontend state.

When admin logs in and visits Keap integration:

Tags should populate automatically from cache if cache is still valid.

Admin should not need to click “Load Tags.”

Cache TTL:

72 hours

Tags should refresh:

Automatically after 72 hours, server side

Immediately when admin clicks “Refresh from Keap”

Database changes
In SystemSettings:

keapTagsCacheJson (json/text)

keapTagsCachedAt (datetime)

keapTagsCacheExpiresAt (datetime)

keapLastTagFetchError (text)

Server logic
Implement:
GET /api/admin/keap/tags
Behavior:

If connected is false:

Return 400 with message “Keap not connected”

If cache exists and now < expiresAt:

Return tags from cache with source="cache"

If cache missing or expired:

Fetch tags from Keap, update cache, return source="keap"

If Keap fetch fails:

If cached tags exist, return them with warning and source="cache"

Also store keapLastTagFetchError

Implement:
POST /api/admin/keap/tags/refresh
Behavior:

Force fetch from Keap, overwrite cache, reset expiresAt

Frontend behavior

On admin Keap integration page mount:

Call /api/admin/keap/status

If connected true, immediately call /api/admin/keap/tags to populate dropdown

“Load Tags” should be removed or renamed:

Change label to “Refresh from Keap”

It should call /api/admin/keap/tags/refresh

Auto refresh every 72 hours
Server side behavior is enough:
