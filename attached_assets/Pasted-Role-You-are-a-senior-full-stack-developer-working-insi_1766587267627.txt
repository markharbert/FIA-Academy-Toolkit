PART 2: Broad Video Format Support (Critical)

Goal
Accept a wide range of upload formats, then normalize them all into a single consistent playback and processing format (MP4 1080p + AAC audio).

Important clarification
WebP is typically an image format, not a video container. Some systems may produce animated WebP files. If an uploaded file is animated WebP, treat it as a supported upload only if the transcoder can decode it. Otherwise, display a friendly error. Prioritize true video containers.

Accepted upload formats (minimum)
Accept these common containers and codecs, as they represent the majority of devices and tools:
Containers:

.mp4 (H.264/H.265)

.mov (common on Apple)

.m4v

.webm

.mkv

.avi

.wmv (Windows)

.flv (legacy)

.3gp (older mobile)

.mpeg / .mpg

.ts (MPEG transport stream, some recorders)

.m2ts (Blu-ray style, some cameras)
Optional / best effort:

animated .webp if ffmpeg supports decoding

.ogv / .ogg video

Validation approach (do not rely on extensions)

Validate by MIME type when available.

Also validate by probing the file content server-side:

Use ffprobe to inspect container, codec, duration, streams.

Reject:

files with no video stream

duration too long if you have limits

zero length or corrupted files

Normalization requirement
Regardless of what is uploaded, always produce:

Final video: MP4 container

Video codec: H.264

Audio codec: AAC

Resolution: 1080p target (downscale if higher, upscale only if you explicitly choose to, but default to no upscaling)

Frame rate: preserve original if reasonable, otherwise cap at 30 fps for size stability

Audio sample rate: 44.1k or 48k

Transcoding rules

Use ffmpeg for transcoding and compression.

Use a balanced preset for quality and file size.

Enable fast start for streaming playback:

movflags +faststart

If audio stream is missing:

still allow upload and scoring if your scoring can run without audio, but transcription will fail

better: require audio stream for transcription and show clear message if missing

Error handling for unsupported formats
If ffprobe or ffmpeg fails:

Mark session as failed with processingError indicating format not supported.

Provide a user-friendly error message:

“We could not process this file. Please upload MP4, MOV, or WebM.”

Log the detailed ffmpeg error server-side for debugging.

PART 3: Backend Upload API

Design requirement
Uploads must not depend on keeping the server request open for the entire file. Use one of these patterns:

Option A (recommended): Pre-signed upload URL to object storage

If project already uses S3, Cloudflare R2, or similar, generate pre-signed URLs.

Browser uploads directly to storage.

Backend then starts processing.

Option B: Chunked upload to backend storage

If storage is local filesystem, implement chunked upload endpoints to handle large files.

Choose the option that matches the existing project. Prefer not to add new services unless needed.

Endpoints required (example)

POST /api/sessions/upload/init
Request:
{
"filename": "...",
"filesize": 12345678,
"mimeType": "video/mp4"
}
Response:
{
"sessionId": "...",
"uploadId": "...",
"uploadUrl": "...",
"chunkSize": 5242880,
"expiresAt": "..."
}

If chunked:
POST /api/sessions/upload/part
Body:

sessionId

uploadId

partNumber

binary chunk

POST /api/sessions/upload/complete
Request:
{
"sessionId": "...",
"uploadId": "...",
"parts": [...]
}
Response:
{
"success": true
}

POST /api/sessions/:id/process
Starts post-upload processing pipeline.

Rules

Auth required for all endpoints.

Ownership required (user can only upload to their own session).

Validate file type and size.

Store upload metadata.

Immediately run ffprobe after upload complete to validate the file and determine processing plan.
