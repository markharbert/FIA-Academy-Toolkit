Role: You are a senior full stack developer debugging an existing Replit web app. Google OAuth completes the provider flow and returns to our app, but the app shows: “Social login failed. Please try again or use email/password.” This means the OAuth callback is being reached, but the backend is failing during one of these steps: token exchange, profile retrieval, user lookup or creation, identity linking, session cookie creation, redirect handling, or frontend auth state refresh.

Your job is to identify the exact failure, fix it, and verify end to end that Google OAuth creates or links a user account and logs them in successfully. After Google works, keep the code structured so Facebook and Apple can work the same way.

Important clarification on “emailing login details”
Do not email passwords. Instead:

For OAuth signups, do not send “login details.” The user logs in with the provider.

If the user wants email/password later, provide a “Set a password” flow in the Account page.

You may send a welcome email that confirms the account was created and tells them which login method they used, without including any password.
Implement that welcome email after successful OAuth signup if email sending is configured.

Reproduce the issue by clicking “Continue with Google.”

Capture and log:

The exact callback URL hit on our server

Query parameters (code, state, error)

Any backend logs during callback

In the browser dev tools, capture:

Identify whether the “social login failed” message comes from:

A backend redirect with an error query string

A failed API call from frontend to confirm session

Step 3: Validate OAuth callback handler correctness
Confirm the backend is doing all required steps.

Required callback flow (must be implemented)

Validate state parameter to prevent CSRF. If state mismatch occurs, it will fail.

Exchange authorization code for tokens.

Retrieve user profile and email.

Determine if email is present.

If no email, route user to Account page with “add your email” requirement.

Find existing identity:

provider = google

providerUserId = google profile sub or id

If identity exists:

Load the user and login

If identity does not exist:

Try to find existing user by verified email

If found, link identity to that user

If not found, create new user record

Create identity record linked to user

Create a session and set cookie properly.

Redirect to dashboard.

Common failure points to check and fix

Email missing because wrong scopes:

Ensure Google OAuth requests the correct scopes:
openid, email, profile

Profile parsing bug:

Ensure code reads email from the correct field.

Database errors:

Missing migration for identities table

Unique constraints failing

User email nullable but code assumes not null

Session cookie not set:

httpOnly cookie options wrong

secure flag forcing HTTPS only when Replit uses a different scheme

SameSite misconfigured causing cookie not stored during OAuth redirect

Frontend cannot detect login:

/api/auth/me endpoint not returning user

CORS or credentials missing

Fetch requests not using credentials: "include"

Step 4: Fix session cookie persistence across OAuth redirect
The most common cause when OAuth “works” but login fails is cookie not being stored or not being sent.

Implement these checks and fixes

Ensure cookie is set on the callback response before redirect.

Ensure cookie settings match the environment:

In local dev HTTP, secure should be false

In production HTTPS, secure true is fine

SameSite rules:

If the OAuth callback is considered cross site, you may need SameSite=None; Secure

But only if you are truly cross site. If frontend and backend share the same origin, Lax often works.

Confirm the cookie domain and path are correct:

domain should usually be omitted to default correctly

path should be /

Confirm frontend requests include credentials:

fetch(..., { credentials: "include" })

Confirm CORS allows credentials:

Access-Control-Allow-Credentials true

Access-Control-Allow-Origin must be the exact origin, not *

It should:

Return user
