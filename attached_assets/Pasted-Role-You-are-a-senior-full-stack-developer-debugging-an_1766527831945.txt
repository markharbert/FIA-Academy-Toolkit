Role: You are a senior full stack developer debugging an existing Replit web app called Fearless Video Coach. Keap OAuth is NOT connecting. The flow reaches Keap, then Keap displays: “There was a server error processing your request.” This is blocking all Keap syncing. Your job is to find the root cause, fix it, and then implement robust contact sync logic plus admin selectable tagging.

Do not assume it works because the redirect to Keap happens. That only proves the authorize URL loads. The error indicates something is wrong in our authorize request, Keap app config, redirect URI, scopes, endpoint host, or state handling.

High Priority Outcomes

Keap OAuth connect completes successfully and returns to our app.

Tokens are stored and refresh works reliably.

When a user signs up (or admin triggers sync), the app:

Creates a new Keap contact if none exists for that email

Otherwise updates the existing contact, no duplicates

Admin can choose which Keap tag is applied to new signups.

Tag application works, and errors are visible in the admin panel.

Part 1: Capture the exact Keap authorize request and why Keap errors

Instrument the server to log the full Keap authorize URL we generate (do not log client secret, but client_id is fine).

Capture the exact authorize URL with ALL query params:

client_id

redirect_uri (exact value after encoding)

response_type

scope

state

Confirm which authorize host is being used:

It must match Keap’s current OAuth authorize endpoint.

Try the authorize URL manually in a browser and confirm it reproduces the same Keap error.

Stop and fix the authorize URL until the Keap page no longer shows the server error.

Part 2: Debug the most common Keap OAuth failure causes in order

You must explicitly check each and report findings in logs.

A. Redirect URI mismatch

Log KEAP_REDIRECT_URI as the app is using it.

Confirm the Keap developer app settings include the exact redirect URI.

Ensure:

https vs http matches

no trailing slash mismatch

correct path, for example:
/api/admin/keap/callback

no additional query params in KEAP_REDIRECT_URI unless explicitly allowed

B. Wrong authorize endpoint or token endpoint

Confirm the correct Keap OAuth authorize URL base.

Confirm token endpoint is correct (commonly https://api.infusionsoft.com/token
).

Make both configurable via env vars:

KEAP_AUTHORIZE_URL_BASE

KEAP_TOKEN_URL
Provide sane defaults that match the official Keap docs.

C. Invalid or malformed scopes

Reduce scopes to the minimum needed for:

contact create and update

tag apply

optionally tag list

Ensure the scope parameter formatting is correct:

space separated list before URL encoding

Implement KEAP_SCOPES env var and log its final value.

D. state parameter and CSRF storage

Ensure state is generated securely and stored server side (session or DB).

Ensure callback validates state.

If state mismatch, show a clear admin facing error screen.

E. URL encoding issues

Ensure redirect_uri is URL encoded exactly once.

Ensure scope is URL encoded properly.

Ensure no double encoding.

Part 5: Contact sync must create or update, never duplicate

Implement a single robust function:
syncUserToKeap(userId, mode)

mode:

"auto" for signup

"manual" for admin triggered

Rules

Only sync if:

Keap is connected

user has email

user consent is true (if your app requires consent)

Normalize email:

trim and lowercase

Contact lookup logic
Before creating a contact, attempt to find existing contact by email.
If found:

Update it

Store keapContactId on user if missing
If not found:

Create contact

Store keapContactId on user

If the user already has keapContactId:

Prefer update by ID

If update fails because ID not found, re search by email, then create only if still not found

Apply tags
After create or update:

If keapDefaultTagId is set:

Apply the tag to the contact

Ensure tag application is idempotent:

If already tagged, do not fail

If tagging fails:

Log error

Record last sync error in a user keap sync log

Do not block signup or login

Data to sync
Minimum:

email

firstName

lastName

displayName

signup source field like "Fearless Video Coach"
Optional:

lastLoginAt if tracked

consent timestamp if desired
